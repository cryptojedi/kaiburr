\section{Revisiting the noise distribution}
\label{sec:distribution}
Even though the resulting public key and ciphertext sizes at $k=7$ remain relatively small,
increasing $k$ further is not possible without affecting correctness. The natural way to
restore correctness would be to increase the modulus $q$ which allows for larger error growth while
keeping the decryption-failure probability within the target bound. However, changing $q$
would require modifying the arithmetic parameters of ML-KEM and prevent direct reuse of its
optimized software and hardware implementations.

Throughout this work, we therefore keep the ring parameters fixed at their ML-KEM values,
$n=256$ and $q=3329$, for the same design considerations discussed in the Kyber Round 1
and Round 2 submissions \cite{kyberround1,kyberround2}.
 The ring dimension is fixed at $n=256$ because the scheme encapsulates
a $256$-bit key, so that a single coefficient carries a single key bit. A smaller $n$ would
require packing several key bits per coefficient, forcing lower noise and hence lower
security, while increasing $n$ would fundamentally change the design rather than simply
increase the security margin \cite{kyberround1}. The modulus $q=3329$ is the small prime
satisfying the NTT-enabling condition $n \mid (q-1)$, notably weaker than the
$2n \mid (q-1)$ condition one might expect, which Kyber deliberately does not require
\cite{kyberround2}. It was reduced from the round-1 value $7681$ to recover the bandwidth
spent by dropping public-key compression and co-tuned to balance ciphertext size,
failure probability, and security.

This is not to say that $k$ is the only parameter that can be modified. We
focus on changes that preserve the core structure of Kyber:
the ring $\mathbb{Z}_q[X]/(X^{256}+1)$, the NTT implementation and its
constants, and the existing analysis framework. The module
rank $k$ qualifies trivially. So does the error distribution. 
Since the noise only affects the error term and does not interact with the arithmetic structure or the NTT, 
it can be replaced without modifying the core implementation. What it changes are sampling procedure, the MLWE hardness estimate, and the
decryption-failure probability, all of which can be analyzed over the same ring
using the existing security estimation framework.

In this sense the error distribution is the main degree of freedom that moves
the security and correctness without changing what the essence of the scheme is,
which is exactly what we exploit. Specifically, to move beyond the warmup security ceiling, we need a noise
distribution that reduces decryption failures as $k$ increases while
remaining as efficient to sample as Kyber's centered binomial
distribution. In particular, it should still admit a simple branchless,
constant-time sampler. This makes simply adopting a discrete Gaussian, as in FrodoKEM, less suitable.

\subsection{A parameterized noise distribution}
We introduce a one-parameter family $f(t)$ on $\{-2,-1,0,1,2\}$, defined by
$$
  \Pr[\pm2]=2^{-t},\qquad
  \Pr[\pm1]=\tfrac14,\qquad
  \Pr[0]=\tfrac12-2^{-(t-1)}.
$$
The probabilities at $\pm1$ remain fixed, while the probability mass at
$\pm2$ decreases exponentially with $t$.

Samples from $f(t)$ can be generated using Algorithm~\ref{alg:ft-sampler},
which requires only uniform random bits and simple bitwise operations.
The sampler is branchless and therefore runs in constant time. We
machine-checked both constant-time (CT) and speculative constant-time
(SCT) in Jasmin~\cite{jasmin}.

The standard deviation is $$\sigma(t)=\sqrt{0.5+2^{3-t}},$$
which decreases from $1$ at $t=4$ toward $\sqrt{0.5}$ as $t$ increases. $f(t)$ can also be seen as a generalization of
 Kyber's noise distribution. In particular,
$f(4)=\mathrm{CBD}_2$, the distribution used in ML-KEM-768 and ML-KEM-1024,
and $$\lim_{t\to\infty}f(t)=\mathrm{CBD}_1.$$

\begin{algorithm}[t]
\caption{Branchless sampler for $f(t)$}
\label{alg:ft-sampler}
Sample independent bits $a_1,\ldots,a_t\in\{0,1\}$\;
$s \gets 2a_t-1$\;
$m \gets 1-a_1+2\prod_{i=1}^{t-1}a_i$\;
\Return $s\cdot m$\;
\end{algorithm}

\subsection{Why thinning the tail is an efficient trade}

The goal of $f(t)$ is not to reduce the overall noise, but to
selectively reduce the part of the distribution that contributes most to
decryption failures. In Kyber's centered binomial distribution, the size of the
noise is controlled by a single parameter $\eta$, which changes both the
main mass and the tail of the distribution. In contrast, $f(t)$ keeps the
probability at $\pm1$ fixed while reducing the heavier $\pm2$ tail.
This lets us decrease the variance that drives failures without removing all of the noise contributing to
MLWE hardness.

A further advantage of the one-parameter family is that it provides a
continuous range of noise levels. Kyber's centered binomial distributions only provide the two choices
$\eta=1$ and $\eta=2$, with standard deviations $\sigma\approx\sqrt{0.5}$
and $\sigma=1$, respectively. By varying $t$, $f(t)$ smoothly fills the range between
these two extreme values and allows the noise level to be tuned for each module rank $k$ rather than
selecting a fixed distribution that may be unnecessarily conservative.

\subsection{Limit of the noise family}

The flexibility provided by $f(t)$ is not unlimited. The smallest noise
achievable by this family is the limiting distribution $f(\infty)$, where
$$
\Pr[\pm1]=\tfrac14,\qquad
\Pr[0]=\tfrac12,\qquad
\Pr[\pm2]=0,
$$
with minimum variance $\sigma^2=0.5$. Even at this limit, the accumulated
error eventually causes the decryption failure probability to exceed the
$2^{-128}$ threshold. For $n=256$ and $q=3329$, this occurs at $k=30$,
so $k=29$ is the largest rank supported by the entire family. Beyond this point, 
further increases in security would require changing other parameters such as $n$ or $q$.

\subsection{Selecting $t$}
For each rank $k$, correctness and security define an acceptable range of
values for $t$. We select representative values within this range based on
vectorization efficiency. Since $t$ determines the number of random bits
used per sample, small byte-aligned values provide a natural trade-off
between sampling cost and noise reduction. Some of these values are natural:
$t=4$ recovers the $\mathrm{CBD}_2$ sampler and serves
as our anchor; $t=8$ admits one-byte-per-coefficient SIMD packing; and
$t=6$ sits between them, spending fewer PRF bytes and offering more security
per dimension at the cost of less regular packing. For each selected value of $t$, 
we then increase $k$ until reaching the largest rank that satisfies the decryption-failure bound. The theoretical
limit of the noise family is $k=29$, but these larger ranks are not practical
because their communication cost exceeds our target FrodoKEM-640 bandwidth (9616 bytes pk, 9720 bytes ct). As a result,
we choose parameter sets that balance security, correctness, and
communication: $k=24$ for $t=8$, with analogous choices for $t=6$ and $t=4$ (Table~\ref{tab:kaiburr-params}).
